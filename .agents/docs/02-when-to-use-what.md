# When to Use What

## Use `$ticket-workflow`
- company work
- existing repository
- ticket-driven changes
- Slack/Linear context
- need strict scope control

## Use `$build-workflow`
- new product or feature
- need scope/spec/architecture/checklist first
- phased implementation

## Use `$stack-workflow`
- adding a new framework
- major version changes
- turning docs into reusable conventions

## Ask for specialists when
- UI / design system complexity -> `frontend-specialist`
- Expo / mobile constraints -> `mobile-specialist`
- agents / RAG / LangGraph / Agno / MCP -> `ai-systems-specialist`
